Pets are pictures + JSON. Full stop.

A pet pack is one PNG sprite sheet and one manifest. There is no plugin system and no scripting — not as an option that's off, but as a thing that doesn't exist. Packs made for the delisted DPET : Desktop Pet Engine import unchanged.

Make your own pet →

{
  "name": "Station Cat",
  "spriteSheet": "cat.png",
  "frameWidth": 128,
  "frameHeight": 128,
  "animations": {
    "stand": { "row": 0, "frames": 4 },
    "walk":  { "row": 1, "frames": 4 },
    "climb": { "row": 2, "frames": 2 },
    "fall":  { "row": 5, "frames": 3 }
  }
}

Built for the zips people actually share

Desktop pet assets travel as zip dumps on Reddit and Discord — and some of those zips carry more than sprites. CatPetStation's importer assumes every archive is hostile:

  • Allowlist extractiononly verified .png and .json ever leave the archive — executables, scripts, and shortcuts are skipped and reported to you.
  • Zip-slip proofarchive paths are never used; content is written to file names the app generates itself.
  • Bomb guardsentry counts, per-file and total size caps, and declared-length verification stop decompression bombs.
  • No disguisesPNG magic bytes are checked, manifests must fully validate, and Windows tricks like alternate data streams are refused.

Read the safe-import guide — including how to handle community asset dumps before they ever reach an importer.

Get started in one line

# with the .NET 10 SDK installed
git clone https://github.com/YOUR-USER/CatPetStation && cd CatPetStation
dotnet run --project src/CatPetStation.App

Or grab the self-contained build from the latest release — no runtime install needed.
